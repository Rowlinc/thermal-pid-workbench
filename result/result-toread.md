# 示例结果怎么读

这是仓库随附的离线结果快照，原始数据来自默认配置的测试运行。
对象为 FOPDT：K=1°C/输出单位、τ=120 秒、θ=10 秒；输出为 0–100%，采样周期 1 秒，每秒最大输出变化 10 个百分点。

在项目根目录运行 `python pid_project.py` 可执行默认示例；新生成的报告位于 `results/project/report.html`，本文件夹 `result/` 保留参考快照。

**本次任务是 30°C → 100°C，运行了 600 秒，未启用 LLM，也未连接设备。系统最终选择 Z-N PI：Kp=3、Ki=0.04、Kd=0。**

先打开 [这次的报告 result.html](result.html)，按下面顺序看。

**1．先看报告顶部：这次到底在验证什么**

我们要确认三件事：

- 任务是否正确：这次是 **30→100°C**。
- 模式是否正确：这次是 **test，离线仿真**。
- 是否生成合格参数：这次是 **有合格建议**。

这一步避免拿错报告，或者把示例模型的结果误认为自己真实设备的效果。

**2．看第一张指标表：先判断合格，再比较好坏**

这次的结果是：

| 组别           | 超调      | 末段平均温差 | 调节时间 | 最高温度  | 判定     |
| -------------- | --------- | ------------ | -------- | --------- | -------- |
| `original_zn`  | 4.168%    | 0.13489°C    | 412 秒   | 102.918°C | 未达标   |
| `corrected_zn` | 3.601%    | 0.10050°C    | 401 秒   | 102.520°C | 未达标   |
| `selected`     | 约 0.001% | 0.00061°C    | 270 秒   | 100.001°C | **达标** |

三个名字分别表示：

- `original_zn`：原辨识方法得到参数，再用 Z-N PID。
- `corrected_zn`：修正辨识或使用提供的模型，再用 Z-N PID。
- `selected`：比较 Z-N PID、Z-N PI、SIMC PI 后选出的方案。

前两组失败的原因都是 `max_temperature_c`：**超过你设置的最高温度 102°C。**

所以这次先得出一个明确结论：**selected 满足全部要求，另外两组没有满足全部要求。**

再看性能：selected 更早稳定、末段温差更小，IAE 和输出变化总量也更小。但这只是当前配置模型上的结果。

**3．看“温度响应”图：理解升温过程**

横轴是时间，单位秒；纵轴是温度，单位 °C。虚线标的是目标 **100°C**，图例对应三组曲线。

重点看：

- 是否超过目标太多。
- 是否在目标附近来回振荡。
- 最后是否接近目标。
- 多久进入目标附近并保持住。

selected 的仿真过程是：

| 时间   | 温度        |
| ------ | ----------- |
| 0 秒   | 30.00°C     |
| 100 秒 | 75.26°C     |
| 200 秒 | 95.74°C     |
| 270 秒 | 99.02°C     |
| 400 秒 | 99.96°C     |
| 600 秒 | 约 100.00°C |

**“调节时间 270 秒”不表示第 270 秒刚好达到 100°C。**
稳定温差带是 ±1°C，即 **99–101°C**。它在约 270 秒进入这个区间，之后一直保持到仿真结束，所以算作稳定。

开头温度会从 30°C 小幅下降到约 29.2°C。这是当前模型中存在 10 秒延迟、初始输出为 0 的结果：加热影响还没到达对象时，对象仍在降温。

**4．看“控制输出”图：控制器怎样完成升温**

这张图表示加热功率或阀位怎样变化。你这次输出单位是 **%**，范围 **0–100%**。

selected 的输出过程是：

- 从 0% 开始，每秒最多增加 10 个百分点。
- 第 10 秒达到 100%，保持一段时间以加快升温。
- 接近目标后逐渐减小输出。
- 最后稳定在约 **80%**，维持 100°C。

**温度达到目标后，输出不一定降到 0。** 对象持续散热，通常需要持续加热才能维持温度。

图上主要检查输出是否超出范围、是否频繁大幅来回变化、是否长期卡在上限。到上限本身不一定失败，升温初期用满功率可能正常。

`output_TV` 是所有相邻输出变化的绝对值之和。selected 约为 **120**：大致是先从 0 升到 100，再从 100 降到 80。它不是能耗，也不是“输出超过了 100%”。

**5．看“Z-N / SIMC 初始候选”表：为什么选了它**

这张表回答的是：**选择发生之前，每个候选表现怎样？**

这次的表现：

| 候选    | 实际使用参数 Kp、Ki、Kd | 结果                                    |
| ------- | ----------------------- | --------------------------------------- |
| ZN_PID  | `3、0.04、72`           | 最高温度超限                            |
| ZN_PI   | `3、0.04、0`            | **全部达标**                            |
| SIMC_PI | `2.4、0.02、0`          | 末段平均温差约 0.445°C，超过 0.3°C 上限 |

因此 selected 选中了 **ZN_PI**。

表里的“公式计算”是原始建议，“护栏后”才是真正进入仿真的参数。下面的“增幅过大……”是在解释哪些参数被限制了。

SIMC 没有超调，但这次响应较慢，最后一段还不够接近目标。所以**不能只看超调这一列，也不能固定认为某个算法最好。**

**6．最后看 pid.json：最终交付的是什么**

打开 [最终参数 pid.json](pid.json)，本次建议为：

```
形式：并联式
时间单位：秒
Kp = 3
Ki = 0.04
Kd = 0
输出单位：%
采样周期：1 秒
```

Kd=0，所以它实际是 **PI 控制器**。

采用参数时，要同时核对参数形式、时间单位、输出量纲和采样周期。不能只抄三个数字；例如某个控制器要求的是 Kp、Ti、Td，就需要转换。

本次 LLM 历史为空，是因为没有启用 LLM，并非漏跑。需要进一步核对时：

- [summary.json](summary.json)：完整配置、指标、护栏和调优记录。
- [metrics.csv](metrics.csv)：方便用表格软件比较。
- `selected.csv`：每个采样时刻的温度与输出。

**这次可以把报告读成：在当前示例模型和要求下，护栏后的 Z-N PI 能完成 30→100°C，约 270 秒进入稳定温差带，几乎没有超调，因此成为最终建议。** 这些是仿真预测；换成自己的化工对象，需要先输入该对象的模型或合适的历史数据再运行。
