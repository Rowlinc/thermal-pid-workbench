# 护栏策略修正说明

## 为什么修改

旧策略对离线公式候选也使用初始参考 PID 的增幅限制。默认参考 `1/0.01/0` 配合 P 三倍、I 四倍限制，使 Z-N PI 的 `10.8/0.324324/0` 与慢对象的 `5.4/0.040541/0` 都被裁剪成 `3/0.04/0`。这改变了算法参数，也使不同对象的结果失去区分。

相对已有控制器限制增幅适合设备参数变更；将任意默认值当成离线公式的基准不合理。修正后的策略把这两个用途分开，继续使用相同 `pid_safety.py` 做确定性检查。

## 当前默认：auto

| 阶段 | test 模式 | use 模式 |
|---|---|---|
| 初始公式候选 | 有效数值＋绝对上下限 | 再限制相对实际设备 PID 的增幅 |
| LLM 每轮 | 有效数值＋绝对上下限＋相对当前仿真参数的增幅 | 相同 |
| 最终参数 | 有效数值＋绝对上下限 | 再检查相对实际设备起始 PID 的总增幅 |

全部参数继续经过输出限幅、速率限制、抗积分饱和和完整任务仿真评价。不达标时推荐为 null。绝对上下限是用户设置的程序参数范围，不是自动推导出的化工过程安全边界。参照值为零时仍只有绝对范围约束，避免零乘倍数导致该项永远无法启用。

配置位置：

```json
"controller": {
  "guardrail_policy": "auto"
}
```

设置 `relative` 可以复现修改前的行为。省略字段采用新默认 `auto`。报告及 summary.json 记录配置策略和各阶段实际检查策略。

## 修改后的验证

在相同六场景中，仅切换护栏策略、关闭 LLM 随机建议，进行受控对照：

| 达标场景数 | 旧策略 relative | 新策略 auto |
|---|---:|---:|
| 原辨识＋Z-N PID | 1/6 | 5/6 |
| 修正辨识＋Z-N PID | 1/6 | 6/6 |
| 多候选择优 | 5/6 | 6/6 |

30→100°C 场景：修正组公式参数 `14.4/0.72/72` 不再裁剪到 `3/0.04/72`，最高温度由102.520°C变为100.304°C，调节时间由401秒变为193秒。选优组此时选中 Z-N PID，结果与修正组相同。

应同时注意取舍：30→100°C 的选优组相较旧策略，调节时间由270秒缩短到193秒，但输出TV由120.000增至152.581，并非所有指标都改善。优先达标，再按当前配置的排名规则比较IAE和输出变化。

另以用户当前 project.json 完成一次联网LLM测试，三组均达标；全部424项测试及11项子测试通过。这不是生产设备验证。

## 如何使用此前结果

此前5/6对1/6的场景比较可以保留为“旧相对增幅策略下”的实验记录，不能把较大差距直接归因于整定算法或新流程普遍优于原项目。当前更合理的对照中，修正组和选优组在六场景中结果相同，说明新增候选在这批任务里没有带来进一步改善。

原辨识组始终是统一框架中的原辨识算法＋Z-N PID基线，不是完整原项目独立执行。不同护栏策略、LLM开关、场景和配置哈希的数据应分别引用，不能混合成同一组实验结论。历史结果未覆盖，新结果在各自时间戳目录内保存。
