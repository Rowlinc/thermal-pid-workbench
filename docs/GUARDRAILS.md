# 参数护栏与仿真评价（0.4.3）

参数护栏检查完整建议，任一项不合规就拒绝整组，保留原建议及原因。不会把 Kp=10 自动改成上限 3，也不会自动放宽限制或重新辨识对象。超限不代表算法计算错误、参数效果差或模型错误。

## 检查阶段

| 阶段 | test（默认 auto） | use |
|---|---|---|
| 初始公式候选 | 有效数值、绝对上下限 | 再检查相对实际设备起始 PID 的增幅 |
| LLM 建议 | 有效数值、绝对上下限、相对当前仿真 PID 的增幅 | 相同 |
| 最终建议／写入 | 有效数值、绝对上下限 | 再检查相对设备起始 PID 的总增幅；写入前独立重查 |

controller.guardrail_policy=relative 让 test 初始公式也检查相对增幅，但超限仍拒绝，不再复现旧裁剪行为。参照为零时倍数上限无法定义，该项只检查绝对范围。参数内部统一为秒制并联式非负幅值，方向由过程 K 决定；配置、导入和导出负责形式与时间单位转换。

Z-N 被拒绝后继续测试 SIMC 等其他候选。所有初始候选都被拒绝时，保存正常运行记录、原因和 pid=null，返回无可用建议，不调用 LLM，不生成虚构曲线。此时检查数据、增益尺度、单位、参数形式和配置边界；可以调整 SIMC 的响应时间 lambda。程序不把一次超限作为重新辨识的证据。

## 状态与公平比较

| 状态 | 含义 |
|---|---|
| ACCEPTED | 参数检查通过，可以进入仿真；guard_status 记录本层状态 |
| REJECTED_GUARDRAIL | 参数超限、缺失或无效；整组拒绝，未仿真，性能指标为空 |
| FAILED_SIMULATION | 仿真求解失败、非有限响应或触发仿真停止条件 |
| FAILED_EVALUATION | 仿真完成，但超调、偏差、调节时间等评价未达标 |
| PASSED | 配置模型上的仿真及评价通过 |

summary.json 的 candidates 保留已完成候选，rejected_candidates 和 failed_candidates 单独保留拒绝与求解异常；报告和界面均显示原因。仿真触发停止条件时保留已采集曲线与诊断，但状态为 FAILED_SIMULATION。参数被拒绝的算法没有控制效果的胜负，不能用空指标判定它比别的算法差。

旧版连续调优核心也经过当前统一拒绝护栏。legacy_route 的初始化或建议因此可能被拒绝、路线可能未形成完整对照。它保留旧辨识与调优策略，但不是未修改原项目的独立运行。旧报告中裁剪后的数值是历史记录，不能当成本版结果。

## LLM 重试预算

```json
"tuning": {
  "rounds": 4,
  "max_guardrail_retries_per_round": 2,
  "max_llm_requests_per_route": 12
}
```

新路线最多仿真 4 组通过参数检查的建议。每轮首次建议被拒绝后最多重试 2 次；拒绝不占有效仿真轮数。程序反馈原建议、允许范围和拒绝原因，继续请求完整 p/i/d。持续拒绝或请求上限耗尽时结束该路线，保留已验证的最佳结果，继续其他路线。无效的 DONE 不会完成调优。

每条路线最多调用 12 次建议接口，整个任务最多为实际参与路线数乘以此上限；最多五条路线时为 60 次。网络层失败重试另受 llm.max_attempts 约束；建议接口调用次数不是精确的 HTTP 次数、token 或费用上限。旧连续核心保留按采样窗口评价计轮的语义，拒绝重试复用同一窗口，不重新采样、不下发参数。

## 参数合法与控制效果分开判断

通过第一层护栏的参数仍可能导致过冲、长期偏差或振荡。第二层对同一完整任务进行仿真与性能评价，检查执行器输出限幅、速率限制、抗积分饱和和评价门槛，只有合格结果才能成为推荐。模型偏差可通过 gain_scale、扰动和噪声配置测试；本程序不会声称覆盖所有未知模型偏差。

use 模式保留设备配置一致性、当前工况、写入开关、参数回读与有限时间监测等独立检查。参数护栏和离线评价均不能代替现场 DCS/PLC/SIS 的既有保护体系。
